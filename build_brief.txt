# Build Brief: **High-Resolution WebGPU Murmuration Engine**

## Project title

**Murmuration Engine**

A real-time, high-density flocking simulation that runs natively and in the browser, rendering tens of thousands to hundreds of thousands of bird-like agents with emergent wave behavior, cinematic lighting, and interactive controls.

The pitch:

> I built a Rust/WebGPU simulation engine for high-resolution murmurations, using GPU instancing, spatial acceleration, flocking dynamics, coherent noise fields, and perturbation-wave propagation to create large-scale emergent motion in real time.

---

A simulation where thousands of small agents move like a starling murmuration.

The user sees:

A huge flock moving through the sky

Camera controls and cinematic lighting
Sliders for simulation behavior
Browser demo + native high-performance build

The technical artifact is not just “boids.” It is a **GPU-accelerated multi-agent visual simulation**.

# 5. Core simulation model

Each bird is an agent with minimal state.

```rust
#[repr(C)]
#[derive(Clone, Copy)]
pub struct Bird {
    pub position: [f32; 4],
    pub velocity: [f32; 4],
    pub aux: [f32; 4],
}
```

Use `aux` for:

```txt
aux.x = fear
aux.y = phase
aux.z = local_density
aux.w = random_seed or species_bias
```

Why `[f32; 4]`?

Because GPU buffers like 16-byte alignment. It keeps WGSL interop clean.

# 6. Flocking forces

Each frame, compute:

```txt
separation
alignment
cohesion
boundary force
curl noise / wind
predator avoidance
fear-wave propagation
turn-rate limiting
speed clamping
```

The force equation:

```txt
force =
    separation_weight * separation
  + alignment_weight  * alignment
  + cohesion_weight   * cohesion
  + boundary_weight   * boundary
  + noise_weight      * curl_noise
  + predator_weight   * predator_avoidance
  + fear_weight       * fear_response
```

Then integrate:

```txt
velocity += force * dt
velocity = clamp_speed(velocity)
velocity = limit_turn_rate(previous_velocity, velocity)
position += velocity * dt
```

The **turn-rate limiter** is crucial. Without it, birds feel like particles. With it, they feel like living bodies.

# 8. Rendering design

You should not render full bird meshes at first.

Use three rendering levels.

## LOD 0: dots

For far birds or very large counts:

```txt
1 point or billboard per bird
fastest
good for 500k–1M particles
```

## LOD 1: V-shaped birds

For the main version:

```txt
tiny velocity-oriented triangle/V mesh
3–8 triangles per bird
GPU instanced
looks bird-like without expensive animation
```

## LOD 2: animated impostor birds

For close-up mode:

```txt
billboard sprite or tiny mesh
wingbeat based on phase
only for near-camera birds
```

Start with **LOD 1**.

Each bird instance needs:

```txt
position
velocity direction
fear/local density
phase
```

The shader orients the V-shape along velocity.

# 9. Visual tricks that make it look real

## A. Turn-wave shading

This is probably the most important aesthetic trick.

When birds turn, the visible surface area changes. Approximate that with:

```txt
brightness = abs(dot(normalized_velocity, view_direction))
```

or a variation using side-vector.

This makes large coordinated turns show up as dark/silver ripples.

## B. Fog and depth fade

Use atmospheric perspective:

```txt
farther birds become lighter / softer
background haze increases with depth
```

## C. Density-aware alpha

Approximate dense areas by making birds slightly darker or more opaque when local density is high.

```txt
alpha = base_alpha + local_density * density_alpha_scale
```

## D. Trails

Add subtle motion trails, not neon sci-fi trails.

Good trails make the flock feel like fluid.

## E. Sunset sky

Use a procedural gradient sky:

```txt
horizon warm
zenith cooler/darker
sun direction controls highlight
```

This makes screenshots instantly more compelling.

# 10. Neighbor search strategy

This is the hardest simulation part.

## M0 version: no neighbor search

For the first visual demo, use fake flocking:

```txt
global center attraction
curl noise
boundary force
velocity smoothing
```

This gets motion on screen fast.

## M1 version: CPU spatial grid

Uniform grid:

```txt
cell_size = neighbor_radius
hash position into grid cell
for each bird, check neighboring 27 cells
```

This lets you support maybe:

```txt
10k–50k birds
```

depending on implementation.

## M2 version: GPU approximate neighbor search

For high-res WebGPU, you have options.

The simplest feasible version:

```txt
fixed-size spatial grid
atomic counters per cell
fixed max birds per cell
each bird checks nearby cells
```

This is not perfect, but it is very buildable.

The buffers:

```txt
bird_buffer_a
bird_buffer_b
cell_counts
cell_indices
params_buffer
```

Update flow:

```txt
clear cell counts
assign birds to cells
compute flocking forces from neighbor cells
write updated birds into output buffer
swap buffers
render from latest buffer
```

This gives you a real GPU simulation architecture.

## M6 — GPU spatial grid

Goal: real high-res flocking.

Implement:

```txt
cell_counts buffer
cell_bird_indices buffer
clear pass
assign pass
flock update pass
```

Pseudo-pipeline:

```txt
Pass 1:
  clear cell_counts

Pass 2:
  for each bird:
    cell = world_to_cell(position)
    index = atomicAdd(cell_counts[cell], 1)
    if index < MAX_PER_CELL:
      cell_bird_indices[cell * MAX_PER_CELL + index] = bird_id

Pass 3:
  for each bird:
    inspect 27 nearby cells
    accumulate separation/alignment/cohesion/fear
    update velocity and position
```

Acceptance criteria:

```txt
100k+ birds with local flock behavior
no CPU neighbor computation
stable performance
```

This is the technically impressive milestone.

# 12. Initial implementation path

Do **not** start with GPU spatial hashing. That is where projects go to die.

Start like this:

```txt
Week 1:
  Native wgpu renderer + fake murmuration

Week 2:
  CPU spatial grid + real boids + UI

Week 3:
  Predator/fear waves + visual polish

Week 4:
  GPU compute + web target
```

The order matters.

You want a beautiful visible artifact early, then improve the internals.

# 14. Important technical contracts

## Bird GPU layout

```rust
#[repr(C)]
#[derive(Clone, Copy, bytemuck::Pod, bytemuck::Zeroable)]
pub struct GpuBird {
    pub position: [f32; 4],
    pub velocity: [f32; 4],
    pub aux: [f32; 4],
}
```

Contract:

```txt
position.xyz = world position
position.w   = unused or scale

velocity.xyz = world velocity
velocity.w   = speed

aux.x = fear
aux.y = wing phase
aux.z = local density
aux.w = random seed
```

## Params GPU layout

```rust
#[repr(C)]
#[derive(Clone, Copy, bytemuck::Pod, bytemuck::Zeroable)]
pub struct GpuParams {
    pub dt: f32,
    pub time: f32,
    pub bird_count: u32,
    pub _pad0: u32,

    pub neighbor_radius: f32,
    pub separation_radius: f32,
    pub min_speed: f32,
    pub max_speed: f32,

    pub separation_weight: f32,
    pub alignment_weight: f32,
    pub cohesion_weight: f32,
    pub boundary_weight: f32,

    pub noise_weight: f32,
    pub noise_scale: f32,
    pub noise_speed: f32,
    pub max_turn_rate: f32,

    pub predator_pos: [f32; 4],
    pub predator_params: [f32; 4],
}
```

Contract:

```txt
predator_pos.xyz = predator position
predator_params.x = radius
predator_params.y = strength
predator_params.z = enabled flag
predator_params.w = unused
```
